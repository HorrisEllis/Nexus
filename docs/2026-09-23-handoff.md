### 2. Consolidate the axioms
AXIOMS v3.1 is the stated constitution, but axioms are also scattered: per-spec `core.axioms` (AX-001…), README "LAWS", `§` citations in code comments, CLAUDE.md rules, precommit rules. Map every source → one canonical axiom file with stable ids → each spec references ids instead of restating. Map before build; no silent re-numbering (keep an alias table old→new).

### 3. Every change updates .git, .spec, atlas, component registry
Standing rule for each build pass, not optional: commit (with version bump), the affected systems' `.spec` (version_history + components_count), `docs/atlases/<system>-atlas.md`, `registry-components.js` + regenerated `interaction-contract.json`, loom map for non-require edges. 0.39.223 did this for clear-glass; guardian's `.spec` was **not** updated for the account-authority change — do that first.

### 4. Each node owns creating and reading its own nodes
Sovereignty rule (matches architecture-spec memory: "each system owns writing/storing its own data"): a node type's owner module is the only writer AND the canonical reader; other systems go through its API, never read/write its folder directly. Audit: who writes `data/*/nodes/**` today besides the owner (guardian node-registry, clear-glass `data/nodes`, idearium), and add a registry check that flags cross-system writes.

### 5. Guardian jobs physically in the jobs directory → Clear Glass intake → job queue
Current state (checked): `guardian/lib/jobs.js` `_persistJob()` already writes `data/guardian/jobs/<id>.job` (YAML envelope) — but **non-fatally**, as a side copy; the in-memory/JAA job is the truth and nothing reads the file back. Target:
- The `.job` file is written FIRST and is the source of truth (a failed write fails the job loudly, §1.2) — guardian owns creating/reading it (item 4).
- Clear Glass watches the jobs directory (or is pushed the path) and **adds each new `.job` to the intake of its job queue** — reuse `src/downloads/intake-bridge.js`'s intake pattern and the mesh's `dom-transport` job queue (idempotent by jobId) rather than a new queue.
- Job status/result written back to the same `.job` by its owner; Clear Glass reports through guardian's API, not by editing the file.
- Gate: kill guardian mid-job → restart → the `.job` on disk is re-queued once, never duplicated.
