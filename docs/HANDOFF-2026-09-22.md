## On your streaming question

Both halves already exist: the userscripts already MutationObserver +
emit `GUARDIAN_CHUNK` (delta, full, chatUrl); guardian already has
`ncp.stream.chunk` → per-job `_streamBuffer` → `STREAM_TOKEN`. The gap is
that chunks only reach the cockpit, and completion is still decided by
screen-scraping rather than by the stream. So: **DOM synchronisation, not
mutation traversal — and the smaller, stronger form is AN1.** I'd argue
against mirroring the DOM to endpoints: provider DOMs churn with their own
UI noise, so you'd buy bandwidth and instability. Stream semantic deltas
keyed by jobId, which the chunk path already does.

Bigger worry than either: **three transports to a provider tab** means three
homes for the bug you just hit — it was found in one of them only.

## Still open from earlier

**Dangling hooks — diagnosed, not fixed.** A fresh full scan of the same
source produces **zero** dangling hooks (1594 hooks, 2333 wires). Your live
registry has **115 dangling and 7882 edges** — 3× a fresh scan. So it is
accumulated stale registry state, not missing wires. Likely cause traced:
`source-map.js` builds wire ids/uuids from a running index (`source.wire.N`),
so N shifts between scans and a re-scan's wire collides with an older uuid
and is rejected — leaving hooks with no edge. The fix is deterministic
pair-based ids, then a re-scan; nothing else was changed there.

Also unchanged: `.intent` binding undecided; `toolScope` not enforced on the
agent path; qemu VM backend needs a Linux host (9p) — on Windows it reports
unavailable and uses the process sandbox.
