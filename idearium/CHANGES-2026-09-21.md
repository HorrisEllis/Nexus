# 2026-09-21 — idearium stability + specs live in repo compartments

## Why
Boot log 2026-09-21: importing `eravos-complete` (369 files) killed idearium with
`FATAL ERROR: Reached heap limit` at chunk ~313. The spec survived on disk, the repo
never got created ("no repos yet"), and the build queue then asked ChatGPT (via guardian)
to "generate" the ~55 files the import never reached.

## Root cause (measured)
`ingestFilesAsSpec` did markChunkBuilding + completeChunk + loadSpec/saveSpec per file. Every
one parses and re-writes the whole manifest (all chunk content inside it), and `saveSpec`
mirrored the entire manifest AND every chunk's content into the shared store each time, via
loadTable + full-table JSON diff. Heap retained after GC: 17 MB @20 files -> 210 MB @120,
growing with N^2. autopilot caps every child at 1 GB.

## Changes
- spec-engine: mirror rows are metadata only (`contentBytes`, no `content`); a save writes only
  changed rows (O(1) `insert`, signature-cached). Existing fat rows are slimmed once at boot.
- spec-engine: `ingestFilesAsSpec` completes chunks in memory and writes the manifest once;
  `manifest.ingesting` is set at creation and cleared by that one save (crash marker).
  369 files: ~376 ms, 17 MB live (was OOM).
- spec-engine: `listSpecs()` caches summaries by manifest mtime+size.
- api: build-queue poller skips `type:'codebase'` and `ingesting` specs and runs one trigger at a
  time. api: boot `_reconcileSpecRepos()` adopts repo-less specs into compartment-backed repos.
- ui: Build > Spec Library removed; chunk builder is the repo's Spec subtab.
- tests: tests/modules/idearium-ingest-stability.test.js (7), registered in run-all.js.

## Not done / not verified
- Not run against a booted Nexus, a real browser, or a real guardian/ChatGPT tab.
- import-pipeline (repo.chunk.run) memory not measured.
- autopilot heap cap left at its default on purpose; the machine is at the memory-pressure line.
