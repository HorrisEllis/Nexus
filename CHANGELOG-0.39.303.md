## A phase run now ends in a proof run (PH1)
Idearium already built phases piece by piece: the agent writes the phase (Ollama, or whichever agent you pick), a second agent reviews a local draft, and the phase's files are checked for. Now there's a judge at the end that **runs** the work:

1. **The phase states its own end state** in its map under `conditions:`, using the same promise-plus-check shape as the delivery checker (a file, a command, the tests, a page).
2. **After the draft and its review, the proof runs** on the repo the phase was built in.
3. **All met: the run reads proven**, and the proof report is written into that repo.
4. **Any unmet:** each unmet promise, what happened and its likely cause go back to the **same agent, in a fresh chat**, as the next attempt. It's told to fix exactly those and change nothing that already passes.
5. **The attempts are limited:** two by default, adjustable with the `repos.proof_attempts` setting. Then the run reads **unproven**, naming what's still missing.
6. **No conditions declared: the run reads no-proof.** It says so; it's never assumed proven.

This is the first real run of the lab loop, on Idearium's own phase runs. A small local model can build piece by piece, and nothing is accepted without passing its own checks.

**What this means for the maps:** a phase is only proven if it declares checkable `conditions:`. The next step is giving the maps' phases their conditions. The wiring ones can later be generated by the graphs (GG1).
